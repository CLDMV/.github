# v4.21.0 — 2026-08-10

Minor release adding lint + format hygiene to the staging-branch flow: fixes are applied automatically once per run after a merge into `next`/`hotfixes` (never gated on contributors), with a local report-only pre-commit hook that keeps unformatted code out of commits in the first place.

## Added

- **Post-merge lint + format autofix on `next`/`hotfixes`, plus a check-only pre-commit hook.** A once-per-run `lint-format` job (`reusable-lint-format.yml`, not part of the test matrix) runs on `push` events to `next`/`hotfixes` — skipped on the master-sync push and on `chore: bump version`. It applies `format` then `lint:fix`, commits any resulting changes back bot-signed onto the branch (re-triggering CI, which converges once the tree is clean), then runs `format:check` + `lint` as authoritative checks that fail the integration build only on **unfixable** lint. Each phase is `npm run <script> --if-present`, so a repo without the scripts is a graceful no-op, and every phase is overridable per repo via the `ci.yml` `with:` block. Style is therefore never gated on contributors and `next` is already clean by the time it ships. A companion pre-commit hook — installed into `.git/hooks/pre-commit` via a `prepare` script so it composes with, rather than shadows, a global hooks dispatcher — runs `lint` + `format:check` **check-only** (it never writes or re-stages) and rejects a commit on any issue.
