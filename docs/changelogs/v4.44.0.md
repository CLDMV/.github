# v4.44.0 — 2026-11-25

Minor release: the coverage-badge job also publishes a repo's coverage index, the org ruleset lets dev-trunk repos create `dev` and `wip/*` branches, a next-release run that a newer merge overtakes exits cleanly instead of failing, and `package-layout.md` describes publishing declarations as a separate `@cldmv/<pkg>-types` package.

## Features

- **Coverage index on the `badges` branch.** The coverage-badge job now commits the repo's coverage index next to the badge JSON, named per branch like the badge: `coverage-index.json` on the default branch, `coverage-index-next.json` and `coverage-index-hotfixes.json`. It goes out in the same bot-signed commit and on the same push events, never on PRs. On a public repo the file can then be fetched from `raw.githubusercontent.com` without auth, so a repo can run only the tests that reach one source file. A repo that doesn't write `coverage/coverage-index.json` is skipped silently; `coverage_index_path` on `workflow-ci.yml` changes the path or turns it off. The root `.gitignore`'s `coverage/` rule is now anchored to `/coverage/`, since it also hid new files under `.github/actions/coverage/`. Fixes [#540](https://github.com/CLDMV/.github/issues/540) ([#541](https://github.com/CLDMV/.github/pull/541))
- **`dev` and `wip/*` branches allowed by the org ruleset.** Dev-trunk repos keep in-progress work on `dev` and `wip/<who>-<issue>` side branches, but the branch-naming ruleset didn't list either, so every push went through the OrganizationAdmin bypass. `scripts/setup-org-rulesets.mjs` and `docs/conventions/branch-naming.md` now include both. Neither is in `feature-pr.yml`'s auto-PR list, so they still open no PR. The live ruleset changes when the script is re-run with an org-admin token. Fixes [#455](https://github.com/CLDMV/.github/issues/455) ([#538](https://github.com/CLDMV/.github/pull/538))

## Bug Fixes

- **A superseded next-release run exits cleanly.** When two PRs merged into `next` a few seconds apart, the earlier next-release run built its version-bump commit on the old tip and the ref update failed with 422 "Update is not a fast forward", leaving a red run. `github/api/commit` now re-reads the branch on that refusal: if it moved ahead of the commit the run started from, the newer run queued behind it owns the release, so the action sets `superseded=true` and exits 0, and `create-release-pr` / `update-release-pr` skip their remaining PR steps. A branch that was rewritten rather than advanced still fails. Fixes [#467](https://github.com/CLDMV/.github/issues/467) ([#537](https://github.com/CLDMV/.github/pull/537))

## Documentation

- **Declarations in a separate types package.** `docs/conventions/package-layout.md` now describes the layout slothlet uses: the runtime ships only `types/stub/` re-export stubs, and the declarations are published as `@cldmv/<pkg>-types`, carved from the same build and released in lockstep as a satellite (`build_subpackages_command` + `extra_packages`). It covers the `exports`, `files` and optional-peer wiring, `test:types`, the first-publish bootstrap and migration steps for repos that ship or commit `types/` today. The fleet `Node.gitignore` now ignores `dist-packages/`. Fixes [#448](https://github.com/CLDMV/.github/issues/448) ([#539](https://github.com/CLDMV/.github/pull/539))

## Upgrade notes

- No caller changes. The coverage index, the superseded-run handling and the ruleset patterns all ship in the `@v4` reusables and scripts; repos that want the index only need their coverage run to write `coverage/coverage-index.json`.
- Re-run `scripts/setup-org-rulesets.mjs` with an org-admin token to apply the new branch patterns.
