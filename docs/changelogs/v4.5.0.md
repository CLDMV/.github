# v4.5.0 — 2026-05-27

Minor release with the org-onboarding fan-out and per-repo bootstrap action, the notifier rewrite, source-PR grouping in release-PR changelogs, and a sweep adding workflow-level permissions blocks across the board.

## Added

- **Org-wide onboarding fan-out with a per-repo bootstrap action.** One workflow fans out across the org's repos and applies a per-repo bootstrap — rulesets, security settings, and workflow wiring — to each. (feat: 31e5d6f)
- **Notifier rewritten as an enum dispatcher** with a public/private channel split, so release and PR notifications route to the right Discord / Slack / generic webhooks. (feat: 38b12e8)
- **Bootstrap detects a CodeQL default-setup conflict** — initially warn-only, hardened within this cut to disable default setup on conflict (see Fixed). (feat: a1e2485)

## Changed

- **Release-PR changelogs group commits under their source PR.** Secondary commits nest beneath the PR that introduced them, and the squash commit is kept in the grouped child list. (feat: 1b4aa8f, f98eb70)
- **Apache-2.0 `LICENSE` added**, and dependency-review attributed to the bot App. (chore: bef3558)

## Fixed

- **Workflow-level `permissions` blocks added across the board**, including the CI template, so every workflow declares a least-privilege token scope. (fix: 15c576e, 0fdab5c)
- **Local workflows and the CI template cover v4 release PRs** in their `pull_request` triggers and gating `if`. (fix: 0e3405b, 171fd07)
- **CodeQL false positives on the notifier dispatchers** suppressed via a query-filter rather than a path-ignore. (fix: 2678b53, 94a3db4)
- **Bootstrap now disables CodeQL default setup on conflict** instead of only warning. (fix: b33a40f)
