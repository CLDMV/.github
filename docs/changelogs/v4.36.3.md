# v4.36.3 — 2026-11-13

Patch release that fixes how `sync-release-notes` finds a release's PR. v4.36.2 still reported every release PR as not found on llm-translator, including CLDMV/llm-translator#149, so merged release PR bodies kept their relative links.

## Bug Fixes

- **Release PRs found when the commit link fails.** The step finds a release's PR from its release commit (`GET /commits/{sha}/pulls`): a PR merged into the default branch with the release commit as its merge commit, confirmed on the full PR when the listing leaves fields out. That stays the authoritative path. For the bot token on llm-translator it found nothing, so a fallback now answers for those versions: the closed PRs into the default branch, listed once per run and only when needed, keyed by the version in their `release: vX.Y.Z` title (if two claim one version, the most recently merged wins). The Release PR column shows which path matched, for example `#149 (commit)` or `#149 (title)`, and the run logs how many versions each path resolved. The tests include llm-translator's real PR listing. ([#464](https://github.com/CLDMV/.github/pull/464))

## Upgrade notes

- No caller changes needed. Run `sync-release-notes` again in repos that ran it on v4.36.1 or v4.36.2: release bodies are already done, and this run rewrites the merged release PR bodies.
