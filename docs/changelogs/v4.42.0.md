# v4.42.0 — 2026-11-24

Minor release: CI now fails a feature PR whose commit subjects aren't conventional, before a bad subject can reach `next` and change the release version.

## Features

- **📝 Commit Subjects check.** The release bump reads every commit subject in the release range. A subject that isn't `type(scope)!: summary` falls back to a content guess, so `agent add: …` counted as a feature and proposed a minor release for a patch. `workflow-ci.yml` (and this repo's `local-ci.yml`) now run a 📝 Commit Subjects job on pushes to captured feature branches (`hotfix/*` checked against `hotfixes`, the other prefixes against `next`) and on fork PRs. It lists the non-merge commits in the range and fails on any subject that doesn't use one of feat, feature, fix, perf, refactor, test, docs, chore, ci, build, style, revert, deps or release, with one annotation per commit and a table in the step summary. Merge commits are exempt. Pushes to `next`/`hotfixes`/`master`, release PRs, `dependabot/*` and `copilot/*` aren't checked, and a range the API can't list is skipped with a warning instead of failing. When the check fails, workflow-ci reports `docs_only` and `no_node` as `false`, so a caller's existing ✅ Required PR Check fails without any caller change. Fixes [#527](https://github.com/CLDMV/.github/issues/527) ([#528](https://github.com/CLDMV/.github/pull/528))

## Upgrade notes

- No caller changes. A feature branch carrying a non-conventional subject now fails CI: reword it (`git rebase -i <base>`, then "reword") and force-push the branch.
