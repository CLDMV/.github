# v4.8.0 — 2026-05-27

Minor release adding the 3-way GHAS + Secret Protection bootstrap policy, followed by a long tail of bootstrap patches hardening the security-settings API handling.

## Added

- **3-way GHAS + Secret Protection policy in the bootstrap** (`off` | `public-only` | `all`), so an org can enable GitHub Advanced Security and secret protection selectively — e.g. on public repos only. (feat: 3e61359)

## Changed

- **`advanced_security` renamed to `code_security`** to match GitHub's unbundled product naming. (rename: f71b9ff)

## Fixed

- **Bootstrap soft-handles "feature unavailable" responses** from the private-vulnerability-reporting and CodeQL APIs, so a repo or plan that lacks a feature degrades gracefully instead of failing the bootstrap. (fix: 9ce1b26)

## Patch releases

A run of bootstrap and CI patches hardened the security-settings API handling:

- **v4.8.1** — the security-settings diff loop compares against the target state instead of a hardcoded `"enabled"`. (fix: 2f47569)
- **v4.8.2** — only `PATCH` `advanced_security` when the API actually exposes the field, and skip it on public repos (which otherwise 422). (fix: 6afc7a6, e037d1a)
- **v4.8.3** — use the `BOT_APP_CLIENT_ID` secret name in the update-major-tags template. (fix: 39fc06f)
- **v4.8.4 / v4.8.5** — preserve any HTML-marker-fenced block in a PR body by convention, and rename the coverage markers `coverage-badge-*` → `coverage-*` (stripping the legacy names). (fix: b9d15ca, 34c3c61)
- **v4.8.6 / v4.8.7** — CI plumbing: move `paths-ignore` from the trigger to an inline gate, and check out before the relative `paths-gate` `uses:` so its `action.yml` resolves.
- **v4.8.8** — check out before the relative paths-gate use so the local action resolves. (fix: 94ba349)
- **v4.8.9** — short-circuit CI when `next` / `hotfixes` is force-synced to master, with the sync-gate made cascading-skip-safe by running the gates in parallel under `!cancelled()`. (fix: ff9d8bd, 5919dfc)
