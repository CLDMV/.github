# v4.33.1 — 2026-10-12

Patch release so the in-repo "Update Major Version Tags" job steps aside for a `local-` prefixed standalone tag workflow, and a release's Publish run stops reporting `cancelled`.

## Fixed

- **Publish no longer reports `cancelled` when the standalone tag workflow carries the `local-` prefix.** `reusable-publishing.yml` skips its inline `update-version-tags` job when the repository has a standalone `update-major-version-tags.yml`, because creating the release fires that workflow's `release: published` trigger and both jobs would otherwise enter the same `tags-*` concurrency group, where the loser is evicted as `cancelled`. The detection step only looked for the template filename, so a repository that keeps the caller as `local-update-major-version-tags.yml` (this one) still ran both. The release and tags were unaffected, but every Publish run for v4.33.0 ended `cancelled`. Detection now accepts either filename. ([#382](https://github.com/CLDMV/.github/pull/382))
