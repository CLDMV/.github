# v4.33.3 — 2026-10-12

Patch release so updating the rolling `vX` and `vX.Y` tags no longer re-triggers itself, which had queued a new Update Major Version Tags run about every two minutes.

## Fixed

- **A rolling tag that already points at the target commit is left alone.** `update/_impl.mjs`, the step behind `upsert-batch`, re-created and force-pushed `v4` and `v4.33` on every call, even when they already pointed at the right commit. Each push wrote a new tag object, and because the push is made with the App token it fired the `push: tags` trigger of Update Major Version Tags again. That run re-created the tags once more, so once the jobs stopped failing early (v4.33.2) the workflow looped, with the `v4` runs evicted by concurrency and shown as `cancelled`. The update now checks whether the tag already resolves to the target commit and returns without touching it, so a run that changes nothing writes no tag object and fires no further run. A tag at a different commit, a missing tag and a tag that is not fetched in the checkout still take the normal update path. ([#388](https://github.com/CLDMV/.github/pull/388))

## Upgrade notes

- No action for consumers. The fix is reached through the rolling `@v4` tag once `v4` points at this release.
