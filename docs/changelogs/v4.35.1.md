# v4.35.1 — 2026-11-01

Patch release. It separates a package's runtime Node.js floor from the dev toolchain floor. `engines.node` says which Node.js the published package runs on, `devEngines` says which Node.js builds and tests it, and CI's `min_node_version` follows `devEngines`. No workflow behaviour or default values change.

## Documentation

- **`engines.node` is the runtime floor, `devEngines` the dev floor.** `docs/conventions/package-layout.md` no longer tells every library to set `engines.node` to `>=22.22.0`. `engines.node` is the oldest Node.js the published package runs on: the highest of its runtime and peer dependencies' own `engines`, plus whatever the shipped code needs. It is never raised just because the toolchain needs more, so a library built for older Node.js keeps its low floor. The toolchain floor (`>=22.22.0` for vitest 5 and tsup 9) goes in `devEngines.runtime`, which npm checks only on the project's own `install`, `ci` and `run`. The `require(esm)` guard in `index.cjs` now asks for `^20.19.0 or >=22.13.0`, or the runtime floor if that is higher. ([#419](https://github.com/CLDMV/.github/pull/419))
- **`min_node_version` is described as the dev toolchain floor.** The input descriptions in `workflow-ci.yml`, `workflow-release.yml` and `reusable-build-and-test.yml`, and in the `ci.yml`, `publish.yml` and `release.yml` templates, now say to keep it equal to `package.json` `devEngines`, not `engines`. The templates carry the same note next to the input. The default stays `22.22.0`. ([#420](https://github.com/CLDMV/.github/pull/420))

## Upgrade notes

- No breaking changes, and no change to what the workflows do.
- A library that raised `engines.node` to `>=22.22.0` only to match the toolchain can lower it back to its real runtime floor and move `>=22.22.0` into `devEngines`. Leave `min_node_version` in `ci.yml` and `publish.yml` at the dev floor.
