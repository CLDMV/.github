# v4.25.0 — 2026-09-02

Minor release adding a repo-local pre-commit escape hatch, plus two pipeline-robustness fixes: tolerating zero-match `grep` across the release/next-reset shell steps, and guarding the git-hook installer so it can't crash `npm publish`/`npm pack`.

## Added

- **Repo-local `precommit:local` step in the fleet pre-commit hook.** The shared pre-commit hook ran only lint + `format:check`, with no way for a repo to add project-specific commit-time checks short of forking `.githooks/pre-commit` (which drops it off the shared hook and lets it drift). The hook now runs `npm run precommit:local --if-present` after lint/format, so a repo defines a `precommit:local` script for its extra checks (a type-check, a custom audit) and still runs the identical fleet hook. `--if-present` keeps it a no-op for repos that don't define the script, so it's backward-compatible. (#256)

## Fixed

- **Zero-match `grep` no longer aborts the release/next-reset pipelines.** Under GitHub's default `shell: bash` (`-eo pipefail`), a `grep` that legitimately matches zero lines exits 1 and kills the step. The whole bug class is wrapped so an empty result flows through as the valid outcome it is: the release-PR "Compute commit types in range" step (a range of only release/bump commits emptied the first grep, aborting before the release PR was created), the `next-reset` released-major / released-lane parse (a hand-authored or cherry-picked release commit with no parseable `(#N)` aborted the next/hotfixes sync), and the `local-ci` actionlint reporter (`grep -c` exits 1 on a zero count). (#253, fixes #249)
- **`prepare` hook installer can't crash `npm publish`/`npm pack`.** The bare `"prepare": "node .githooks/install.mjs"` also runs on `npm pack`/`npm publish` against the packed tree — where `.githooks/` is excluded from `files`, so node can't resolve the module and aborts the publish before the installer's own guards run. It's switched to the guarded form `node -e "import('./.githooks/install.mjs').catch(()=>{})"`, which no-ops silently in a packed tree and still installs the hook on a normal dev `npm install`. Applied to all four carriers of the bare form, including this repo's own live wiring. (#254, fixes #250)

## Patch releases

- **v4.25.1** — hotfix-redirector: sign the cherry-pick so redirected Dependabot security PRs aren't blocked by required-signatures. The dependabot-security redirect cherry-picked onto `hotfixes` but never imported the bot GPG key and committed under the App-slug identity, producing an unsigned commit that `hotfixes`' required-signatures rule silently blocked. The redirector now imports the signing key, authors the cherry-pick under the real-user bot identity, signs it (`-S`), fails loudly if signing prerequisites are missing, and refuses to push an unsigned commit. (#259, fixes #257)
