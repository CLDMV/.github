# v4.39.3 — 2026-11-19

Patch release: tag-health now re-signs tags whose signature is glued onto the last message line, including the v4.39.2 tags themselves, and the runner image gains the system libraries Playwright's browsers need, plus rsync and the sqlite3 CLI.

## Bug Fixes

- **Glued tag signatures counted as signed.** Tags written before the v4.39.2 newline fix carry `-----BEGIN PGP SIGNATURE-----` on the same line as the end of the message. `git verify-tag` and GitHub treat them as unsigned, but the signed check only looked for the string anywhere in the tag, so tag-health skipped them. A new `hasTagSignature()` helper requires the armor header on its own line, and both `get-detailed-tags` and `getTagInfo` use it. v4.39.2's own tags were cut by the release run before `@v4` moved to the fix, so they are glued too. ([#501](https://github.com/CLDMV/.github/pull/501))

- **Browser tests in the runner image.** Playwright's chromium, webkit and firefox link against libraries the image didn't have (libnspr4, libnss3, libsecret-1 and others), and CI jobs and k3s-test pods have no sudo to run `playwright install-deps` themselves. The image now installs those libraries at build time. Browsers stay per-run downloads (`npx playwright install`), pinned by each repo's Playwright version. A new build gate installs chromium in a scratch project, launches it headless and renders a page. The image also adds rsync and the sqlite3 CLI, both on hosted ubuntu-latest: deploy-flow tests that shell out to rsync skipped without it, and storage tests that inspect a database with sqlite3 failed. ([#504](https://github.com/CLDMV/.github/pull/504))

## Upgrade notes

- No caller changes. The next tag-health run in each repo re-signs the affected tags. The runner image rebuilds when this release reaches master; it grows by the size of the browser libraries.
