# v4.35.0 — 2026-11-01

Minor release. Org bootstrap now creates the orphan `badges` branch, the pre-commit hook can check only staged files, and a new README template and format convention cover CLDMV packages. It also validates the label catalog before the org label sync touches any repo, stops routine Dependabot bumps from being redirected to `hotfixes`, and raises the default CI test floor to Node.js 22.22.0.

## Added

- **Org bootstrap creates the `badges` branch.** The `branches` step of `org-bootstrap-repo` now creates the orphan `badges` branch the coverage-badge job pushes to, holding only a short README, when the repo doesn't have one. An existing `badges` branch is never reset. Two new inputs control it: `badges_branch` (default `badges`) and `create_badges_branch` (default `true`). Under dry-run the step only logs what it would create. Fixes [#403](https://github.com/CLDMV/.github/issues/403). ([#413](https://github.com/CLDMV/.github/pull/413))
- **The pre-commit hook can check staged files only.** `examples/git-hooks/pre-commit` (and this repo's `.githooks/pre-commit`) passes the staged paths to optional `lint:staged` and `format:check:staged` npm scripts when a repo defines them. Repos without them keep running the whole-repo `lint` and `format:check`. `docs/conventions/lint-format-precommit.md` documents the scripts, including a note that `xargs` may split a very large staged list across several runs. Fixes [#401](https://github.com/CLDMV/.github/issues/401). ([#414](https://github.com/CLDMV/.github/pull/414))
- **README template and format convention.** `examples/readme/README.template.md` is the standard layout for a CLDMV package README, with the full badge set and placeholders for package name, default branch and content sections. `docs/conventions/readme-format.md` describes the sections and is linked from the README, `examples/README.md` and the release-flow doc. Wiring the template into scaffolding is listed there as follow-up. Fixes [#404](https://github.com/CLDMV/.github/issues/404). ([#415](https://github.com/CLDMV/.github/pull/415))

## Fixed

- **The label catalog is validated before the org label sync starts.** `sync-org-labels` checks every entry in `data/github-labels.json` first: name and description lengths against GitHub's limits, a six-digit hex colour, aliases as a list of strings, and no name or alias claimed by two labels. Any problem is reported as an error annotation and the job exits before a single repo is touched, instead of failing with HTTP 422 in every repo as the over-long description in v4.33.0 did. `data/github-labels.test.mjs` uses the same check. Fixes [#402](https://github.com/CLDMV/.github/issues/402). ([#412](https://github.com/CLDMV/.github/pull/412))
- **Routine Dependabot bumps stay on `next` when the body quotes a GHSA id.** The hotfix redirector treated any GHSA id in a Dependabot PR body as a security update, and Dependabot copies upstream release notes into the body, which often name advisories. A routine `@cldmv/vitest-runner` bump was redirected to `hotfixes` that way. When the repo's routine Dependabot target is known, the PR's base branch alone now decides. The body is only checked when the target is unknown. Fixes [#409](https://github.com/CLDMV/.github/issues/409). ([#410](https://github.com/CLDMV/.github/pull/410))
- **The CI test matrix starts at Node.js 22.22.0.** The `min_node_version` default in `workflow-ci.yml`, `workflow-release.yml` and `reusable-build-and-test.yml`, and in the `ci.yml`, `publish.yml` and `release.yml` templates, moves from 22.12.0 to 22.22.0, the fleet floor the dev toolchain needs. ([#408](https://github.com/CLDMV/.github/pull/408))

## Documentation

- **Package layout convention drops devcheck.** `docs/conventions/package-layout.md` no longer describes a root `devcheck.mjs`: the `<pkg>-dev` condition picks `src/` or `dist/`, and both are legitimate. It also sets `engines.node` to `>=22.22.0` and shows building the vitest condition settings with `devCondition()`, passing the worker flag through `test.execArgv`. ([#407](https://github.com/CLDMV/.github/pull/407))

## Dependencies

- Dev toolchain bumped to latest: `eslint` 10.14, `prettier` 3.9.10, `@eslint/css` 2, `@eslint/json` 2.1, `globals` 17.14 and the `@cldmv` jsonv packages. ([#416](https://github.com/CLDMV/.github/pull/416))
- `overrides` pin `katex` to `>=0.19.1 <1.0.0` and `minimatch` to `^11.0.3`, the patched versions of the transitive dependencies pulled in by the eslint and `@eslint/markdown` chain. ([#417](https://github.com/CLDMV/.github/pull/417))

## Upgrade notes

- No breaking changes. Consumers get the bootstrap, redirector and CI changes through the rolling `@v4` tag once `v4` points at this release.
- A repo that pins `min_node_version` in its own `ci.yml` keeps that value. Raise it to `22.22.0` to match the fleet floor.
- To use staged-only pre-commit checks, copy the updated hook into the repo's `.githooks/` and add `lint:staged` / `format:check:staged` scripts as shown in the convention doc.
