# v4.20.0 — 2026-08-09

Minor release making the GHAS-gated security workflows viable fleet-wide: private repos default to skipping them cleanly instead of failing, the OpenSSF Scorecard badge publish works again, and a fully successful release run no longer reports itself as cancelled.

## Added

- **Per-repo GHAS opt-out, centrally applied.** `skip_code_scanning` (reusable-codeql) and `skip_dependency_review` (reusable-dependency-review) workflow_call inputs, honored alongside the `CLDMV_SKIP_CODE_SCANNING` / `CLDMV_SKIP_DEPENDENCY_REVIEW` repo variables — either signal activates the skip, giving consumers outside CLDMV a first-class knob. A new `variables` bootstrap phase applies `data/code-scanning-skips.json`: **private repos are skipped by default** (Code Security bills per active committer there) unless opted into the config's `scan` list; public repos always scan; the `skip` section holds explicit per-repo skips regardless of visibility (e.g. a repo with no CodeQL-analyzable source). Third-party orgs supply their own config via the `code_scanning_config` action input (inline JSON or a workspace path) instead of forking this repo. Requires the bot App's "Variables: Read and write" repository permission. (#221, closes #213)

## Fixed

- **OpenSSF Scorecard badge publish rejected with HTTP 400 ("should have exactly 1 'Ubuntu' virtual environment").** scorecard-webapp verifies the static YAML of the workflow named by the OIDC `job_workflow_ref` and requires the scorecard job's `runs-on` to be one literal GitHub-hosted Ubuntu label — the dynamic runner-routing expression (added in v4.19.0) parses as zero labels, so every publish was rejected and the public badge went stale. The publish job now runs on a literal `ubuntu-latest` and is the only job in the verified file referencing `ossf/scorecard-action` (the verifier's job lookup iterates in nondeterministic Go-map order, so two referencing jobs would make verification a coin flip); the no-publish SARIF path moved to `reusable-scorecard-sarif.yml`, keeping the dynamic routing where the verifier never looks. (#218, closes #216)
- **Scorecard on private repos burns paid minutes producing nothing** — scorecard-action force-disables publishing for private repos in its own code (no paid tier exists), so the publish path there ran a full analysis with no output. Every scorecard job now neutral-skips on private repos, gated by an API-probe job (the `schedule` event payload has no repository object to read visibility from). Deliberately visibility-based, not part of the skip-variable mechanism. (#223, closes #216)
- **"Release and Publish" run concluded `cancelled` on fully successful releases.** Creating the GitHub Release fires the consumer's standalone `update-major-version-tags.yml`, which raced the in-line `update-version-tags` job into the shared `tags-*` concurrency group; a group holds only one running + one pending entry, so the losing entrant was evicted as `cancelled` and flipped the whole run's conclusion. The in-line job now detects the standalone workflow and skips when it exists (`continue-on-error` was evaluated and rejected — it converts failure, not cancellation); repos without the standalone keep the in-line tag move, alone in the group. (#219, closes #215)
- **`CLDMV_SKIP_CODE_SCANNING` skip path still failed on GHAS-less private repos** — the empty-SARIF upload hits the same endpoint that rejects with "Code Security must be enabled". The skip path now probes the code-scanning API first and skips the upload on a 403 (a repo without code scanning can't have an enforceable `code_scanning` ruleset rule, so no result is needed); any other response still uploads so genuine failures stay loud. (#220, closes #214)

## Infrastructure

- **`cldmv-runners` image ships `jq`** alongside `gh` (hosted runners preinstall both; the ARC base has neither), and `build-runner-image.yml` prunes the GHCR package to the newest 10 versions after each push — every merge plus the weekly rebuild pushed a new version, unbounded. (#224)

## Docs

- `WORKFLOW-SETUP-GUIDE` / `AGENT-SCAFFOLDING` / `README` updated for the skip mechanisms and the scorecard split; the stale "private repos need a `SCORECARD_TOKEN` PAT" note is gone (private repos now auto-skip scorecard entirely), and the security-baseline trio is documented as safe to scaffold on private repos.
