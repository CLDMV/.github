# v4.38.1 — 2026-11-17

Patch release with two fixes: feature-pr no longer fails on PRs with lots of commits, and sync-release-notes stops misreporting tags and releases that another workflow created during its run.

## Bug Fixes

- **feature-pr on large PRs.** `workflow-feature-pr.yml` passed the full commit list as JSON in an environment variable. On a PR with 144 commits that was about 160 KB, over Linux's 128 KB limit for a single environment string, so the step failed with "Argument list too long" and the PR body and labels stopped refreshing. The feature check and the changelog step now read the list from the `commits-file` that `get-commit-range` already writes. ([#484](https://github.com/CLDMV/.github/pull/484), fixes [#483](https://github.com/CLDMV/.github/issues/483))
- **sync-release-notes and work done by another workflow.** When a tag already pointed at the right commit, `tag/create` skipped it but the sync still counted it as "created tag". It now shows the tag as having appeared during the run. A `422 already_exists` when creating a release (because the publish workflow got there first) now re-reads the release and marks it present instead of failing the repo. ([#482](https://github.com/CLDMV/.github/pull/482))

## Documentation

- The setup guide's "no Node project" section now says that an older `ci.yml` keeps working with `node_project: false`; refreshing it from the template only adds the "No Node project" message on the required check. ([#481](https://github.com/CLDMV/.github/pull/481))

## Upgrade notes

- No caller changes. Both fixes ship in the `@v4` reusables.
