# v4.23.0 — 2026-09-01

Minor release centred on release-artifact and supply-chain signing — GPG-signed release assets and npm publish provenance — alongside SHA-pinning the third-party actions in the pipeline and tightening the workflow-template token permissions the fleet ships to consumers.

## Added

- **Release artifacts are GPG-signed with attached `.asc` assets.** Every package asset attached to a GitHub Release now gets a detached ASCII-armored PGP signature (`.asc`), satisfying OpenSSF Scorecard's `Signed-Releases` check at the signature tier (→ 8) and letting consumers verify release tarballs. The step lives in the `create-release` composite, so the core release and every satellite release in a multi-package publish are covered from one place. It is gated on a GPG key being provided (not on the manual-dispatch `gpg_enabled` tag-signing flag), so real releases are signed on every publish, and it is best-effort: a missing key, signing error, or upload failure warns and leaves the created release intact. (f44553d, #248)
- **npm publish provenance for public packages.** Public packages published to the npm registry now carry SLSA build provenance and a sigstore publish attestation via `npm publish --provenance`, verifiable with `npm audit signatures`. Gated to avoid breakage — public repos only (provenance is public-only), npm CLI only (`yarn publish` has no equivalent), and a caller-supplied custom publish command is left untouched. Covers the core package and every satellite. (#244)

## Changed

- **Third-party actions are pinned by commit SHA.** The genuine external (non-CLDMV) actions used by the reusable workflows — `anchore/sbom-action` and `crazy-max/ghaction-import-gpg` — are pinned to full commit SHAs (version recorded in a trailing comment; Dependabot bumps the SHA + comment together), so a moved upstream tag can't silently change what runs in the CI/release pipeline. Org-controlled `CLDMV/.github` reusables stay on the rolling `@v4` tag by design. (#247)
- **Workflow-template token permissions scoped to least privilege.** The individual-repo workflow templates consumers copy now default to a read-only top level (`permissions: { contents: read }`); templates that previously declared a dangerous top-level write narrow the top level to `contents: read` and move the full scope set onto the reusable-calling job (write granted job-scoped, not workflow-wide). Behavior is unchanged; future syncs inherit the hardening. (#245)
- **Six workflow-example templates normalized to 4-space indent.** `core-cicd/{ci,publish,release,update-major-version-tags}` and `packaging-docs/{docker-publish,sync-org-labels}` are brought into the fleet's deliberate 4-space YAML convention (verified semantically identical). (2c2223a)

## Docs

- **Org profile lists `droidsock`.** droidsock has shipped, so it moves from the "In development" list into "Smart-home & device control" and its placeholder note is dropped. (#246)
