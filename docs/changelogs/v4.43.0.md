# v4.43.0 — 2026-11-25

Minor release: `reusable-docs-publish.yml` can deploy with the GitHub Pages actions instead of pushing a `gh-pages` branch, and release PRs stop re-running the full CI matrix on a commit the push run already tested.

## Features

- **Pages deploy mode for the docs publisher.** `reusable-docs-publish.yml` could only push the build to a `gh-pages` branch, which needs Pages set to "Deploy from a branch", a bot-pushed branch in every repo, and the bot App secrets. `deploy_mode: pages` runs `actions/configure-pages` before the build (the site's base path is in `PAGES_BASE_PATH`), uploads `output_dir` with `actions/upload-pages-artifact`, and deploys it with `actions/deploy-pages` in a separate job under the `github-pages` environment. Pages source must be "GitHub Actions"; no `gh-pages` branch or bot secrets are needed. `branch` stays the default. The reusable no longer declares any permissions, so its jobs inherit the calling job's grant: a `pages: write` request would fail every branch-mode caller at startup, even on a job that gets skipped. The pages-mode caller grants `contents: read`, `pages: write` and `id-token: write`. The bot App secrets are now optional. The `docs.yml` template carries a commented pages-mode job. Fixes [#533](https://github.com/CLDMV/.github/issues/533) ([#534](https://github.com/CLDMV/.github/pull/534))

## Bug Fixes

- **Release PRs no longer run CI twice on the same commit.** The `ci.yml` template ran the full matrix on every release PR (head `next` / `hotfixes`), even when the head was an ordinary merge the push run had just tested. On a repo with a three-hour suite that doubled the wait on every merge. A new `🧭 CI Status Owner` job, backed by the `ci-status-owner` action, reads the head commit and decides which run reports `✅ Required PR Check`. The release PR's own run tests the commit only when the head is the bot's `chore: bump version`, which `commit-gate` skips on the push path. For any other head, the run skips CI and reports under the no-op `⏭️ Required PR Check (reported by the push run)` name. If the commit lookup fails, the run tests the commit anyway. The release PR's coverage badge now refreshes only on bump-commit heads. Fixes [#531](https://github.com/CLDMV/.github/issues/531) ([#532](https://github.com/CLDMV/.github/pull/532))

## Upgrade notes

- **`ci.yml`:** the fix lives in the caller template, so each repo's `ci.yml` has to be re-synced from `examples/individual-repo-workflows/core-cicd/ci.yml` to pick it up. A `ci.yml` that isn't re-synced keeps working with the duplicate runs.
- **Docs publishing:** existing branch-mode callers need no change. To switch to pages mode, set the Pages source to "GitHub Actions" in Settings → Pages and use the pages job from the `docs.yml` template.
