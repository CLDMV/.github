# v4.36.1 — 2026-11-13

Patch release that fixes relative links in changelog files once they become a release PR body, a release commit, a tag message or a GitHub Release. GitHub resolves a PR body against the PR URL and a release body against the repo root, so a link like `../../drivers.md` that works in the file view 404'd on every release page. The changelog files stay relative; the links are rewritten where the file turns into a body.

## Bug Fixes

- **Changelog links pinned per surface.** A shared `pinRelativeLinks` helper in `release-notes.mjs` resolves each relative link and image against the changelog's own folder and turns it into an absolute `https://github.com/<repo>/blob/<ref>/…` URL (`raw/` for images). It leaves absolute URLs, `//host` links, `#anchors`, `mailto:` and other schemes, fenced and inline code, and paths above the repo root alone. The ref depends on where the text ends up. Resolves [#457](https://github.com/CLDMV/.github/issues/457). ([#458](https://github.com/CLDMV/.github/pull/458))
  - **Open release PR body:** the PR's head branch (`next`, or `hotfixes` on the hotfix lane), so the links work during review. generate-comprehensive-changelog takes it as the new `changelog-link-ref` input, which create-release-pr and update-release-pr set to the head branch. It defaults to the release tag.
  - **Release commit:** release-merge moves the head-branch links to `vX.Y.Z` before the squash merge, so the commit on `master` carries tag links.
  - **Tag message and GitHub Release:** the release tag, in create-release and sync-release-notes.
  - **Merged release PR:** once the tag exists, sync-release-notes finds each release's PR from its release commit and points its links at the tag. It also pins bodies from before this release that still have relative links, and leaves bodies that already carry tag links alone. Its App token now requests `pull_requests`.
  - **Backfilled changelogs:** sync-release-notes reads a changelog from the default branch, so it can link to something added after the release. Those links point at the default branch instead of a 404 at the tag.

## Upgrade notes

- No caller changes needed, and changelog files keep their relative links.
- Releases published before this one still show broken links until they are re-synced. Dispatch `sync-release-notes.yml` in each affected repo (dry run first, then a real run) to rewrite the old release pages and release PR bodies.
