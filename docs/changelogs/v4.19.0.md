# v4.19.0 — 2026-08-03

Minor release introducing self-hosted runner routing across the whole reusable fleet, with a patch line stabilizing how nested reusable calls resolve and how the routed jobs actually run.

> Note: no `v4.19.0` tag or GitHub Release exists — the line first shipped as `v4.19.1`. The release commit for 4.19.0 is on `master` (#201).

## Added

- **`runs_on` input on every reusable workflow, with CLDMV-private auto-routing to self-hosted runners.** Every job's `runs-on` resolves in order: the caller's explicit `runs_on` input → the caller repo's `RUNS_ON_DEFAULT` Actions variable (works on all trigger types, including `schedule`, whose event payload carries no repository object) → `cldmv-runners` for CLDMV-owned private repos → `ubuntu-latest`. Private CLDMV CI stops billing GitHub-hosted minutes. (#200, RUNS_ON_DEFAULT resolution in #202)

## Patch releases

- **v4.19.1** — version-lock nested reusable calls and add a CLDMV-private payload fallback for contexts where the event payload can't answer the routing question. (#203)
- **v4.19.2** — restore the deliberate `@v4` pins on nested reusable calls (the version-lock overcorrected — rolling-tag pins are the intended contract between first-party reusables) (#206); derive the release base in the never-supersede concurrency group instead of hardcoding `master`/`main` (#205).
- **v4.19.3** — route the `✅ Required PR Check` mirror job with the same expression as the reusables so private-repo PRs don't queue forever waiting for a GitHub-hosted runner (#209); build and publish the `ghcr.io/cldmv/actions-runner` image (ARC base + `gh`) from source via `build-runner-image.yml` — the stock ARC image ships no `gh`, so every routed job that shelled out to `gh` died with exit 127 (#212).
