# v4.45.0 — 2026-11-25

Minor release: an opt-in cache for expensive build output, an opt-in browser test job in CI, and pnpm and yarn repos publish their packed artifact with `npm publish`, so a pnpm repo's publish no longer fails in the artifact checkout.

## Features

- **Build cache for expensive build output.** Two new inputs, `build_cache_paths` and `build_cache_key_files`, put a cache around the build step for repos whose build produces something slow that rarely changes: a compiled wasm module, a downloaded toolchain, generated code. A new `common/steps/build-cache` composite restores the paths before the build and saves them after it. It's wired into the CI matrix legs, type-check, the coverage-badge and coverage PR-comment jobs, bundle-size (head and base), the release-PR builds and the release build. The key is OS + arch + a sha256 of the build command, the cached paths and the contents of the matched key files, so changing any of them starts from an empty cache. Saves happen only on a miss and only on pushes to the default branch, `next` or `hotfixes`, so PR runs read the cache without writing scopes nobody else can use. With no paths set there is no cache step at all. `workflow-publish.yml` doesn't forward the inputs yet, so publish-time builds are uncached for now. `docs/conventions/build-cache.md` covers the inputs and where they apply. Fixes [#547](https://github.com/CLDMV/.github/issues/547) ([#548](https://github.com/CLDMV/.github/pull/548))
- **Opt-in browser test job.** `workflow-ci.yml` takes a `browser_test_command` (empty by default, which skips the job) and an optional `browser_install_command`. When set, a `🌐 Browser Tests` job runs once on the latest LTS Node with the same gates as the Node legs: install, then the browser install command, then the build, then the tests. It builds with `coverage_build_command` (honouring `skip_build`) rather than `build_command`, because a browser suite usually imports from `src/` and `build_command` can end by removing it. A failure fails the reusable run, so the caller's `✅ Required PR Check` blocks the PR without any change to the repo's `ci.yml`, and the CI summary gets a browser section. Fixes [#546](https://github.com/CLDMV/.github/issues/546) ([#549](https://github.com/CLDMV/.github/pull/549))

## Bug Fixes

- **npm publishes the artifact for every package manager.** With `package_manager: pnpm`, the default publish command was `pnpm publish … --ignore-scripts`. It ran in the expanded build artifact, where pnpm's git checks refused the untracked tree (`ERR_PNPM_GIT_UNCLEAN`), and the publish jobs never set up pnpm or yarn in the first place. The artifact is already packed with the repo's own manager (`pnpm pack` rewrites `workspace:*` to real versions), so `publish-command` now always emits `npm publish --access <public|restricted> --ignore-scripts`, plus `--provenance` for public npm packages. pnpm and yarn repos get provenance on npm for the first time. Satellite packages in `dist-packages/` aren't packed, so their carve step still has to rewrite `workspace:*` itself. `docs/conventions/package-manager.md` describes the split. Fixes [#544](https://github.com/CLDMV/.github/issues/544) ([#545](https://github.com/CLDMV/.github/pull/545))

## Upgrade notes

- No caller changes are required. Both new features are off until a repo sets their inputs in its `ci.yml` `with:` block.
- A repo that moves its browser suite into `browser_test_command` should drop it from `test_command`, or it runs in every Node leg as well.
- A `publish_command` override still wins, so remove any npm pin added to work around the pnpm publish failure once this release is on `@v4`.
