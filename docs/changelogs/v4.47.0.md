# v4.47.0 — 2026-11-28

Minor release: the example `dependabot.yml` moves the CLDMV dev tools in one PR, and its groups no longer depend on the order Dependabot reads them in.

## Features

- **One Dependabot PR for the CLDMV dev tools.** The example `dependabot.yml` gains a `cldmv-dev` group (`@cldmv/*` dev dependencies, minor and patch), so a repo picks up a fleet dev-tool release (vitest-runner, fix-headers, configs, the jsonv plugins) in a single PR instead of having it split across the patch and minor groups. Runtime `@cldmv/*` dependencies get their own `cldmv` group, because they change what the package ships. A `@cldmv` major still comes as its own PR: `dependabot-auto-merge.yml` skips majors, and one inside the group would hold every minor in it back. ([#594](https://github.com/CLDMV/.github/pull/594))

## Bug Fixes

- **Named Dependabot groups no longer depend on group order.** The vitest, eslint and prettier groups relied on Dependabot giving each update to the first group that matches, but grouped PRs filed `vitest` and `@vitest/coverage-v8` under the generic `patch` group anyway. The generic `patch` and `minor` groups now exclude every named family (`@cldmv/*`, `vitest`, `@vitest/*`, `eslint`, `@eslint/*`, `prettier`), and the CLDMV eslint and prettier plugins moved to the `cldmv` groups, so each package matches exactly one named group. ([#594](https://github.com/CLDMV/.github/pull/594))

## Upgrade notes

- The groups live in each repo's own `.github/dependabot.yml`: copy the npm `groups:` block from `examples/individual-repo-workflows/automation/dependabot.yml`, keeping any repo-specific `allow`, `ignore` or `directory` settings. Dependabot reads the file from the default branch, so a repo picks the groups up at its next release. The fleet sync is tracked in [#593](https://github.com/CLDMV/.github/issues/593).
