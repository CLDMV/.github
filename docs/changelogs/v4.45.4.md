# v4.45.4 — 2026-11-25

Patch release: the coverage badge reads `tests failing` on a failed run instead of a stale number, and the Dependency Review comment no longer breaks on PRs that add a large lockfile.

## Bug Fixes

- **Coverage badge on a failed run.** v4.45.3 kept the badge at its last good number when the tests failed, which shows a stale value with nothing to say so, and the failed run's own number isn't accurate either. On a failed run the badge now reads `tests failing` (red, no percentage), and the next passing run publishes a number again. The coverage index and the `coverage` artifact still publish on a failed run, and the job still fails. `push-badge` gains a `tests-failed` input, which `reusable-coverage-badge.yml` sets from the test step's outcome; `publish-badge` stays for callers that want an index-only push. Fixes [#565](https://github.com/CLDMV/.github/issues/565) ([#570](https://github.com/CLDMV/.github/pull/570))
- **Dependency Review comment on large change sets.** The summary-comment step passed dependency-review's full `dependency-changes` output to `actions/github-script` as an env var. On a PR that adds a whole lockfile that one value passes Linux's 128 KiB per-string limit, node fails to start with "Argument list too long", and the required Dependency Review check fails although the review passed. The script now reads the change list from the dependency-graph compare API, the same source the review step uses, only when the OpenSSF Scorecard leg needs it, and warns instead of failing if that call errors. Fixes [#569](https://github.com/CLDMV/.github/issues/569) ([#571](https://github.com/CLDMV/.github/pull/571))

## Upgrade notes

- No caller changes. Re-run a Dependency Review job that failed with "Argument list too long" once `@v4` points at this release.
