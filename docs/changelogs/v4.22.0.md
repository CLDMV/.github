# v4.22.0 — 2026-08-19

Minor release making a committed changelog file drive the release-PR body (and therefore the squash-merge message on the release branch), alongside a command-injection hardening of the docs-site publisher, a coverage-badge rounding fix, and the prettier + eslint toolchain landing on this repo itself.

## Added

- **A committed per-version changelog file becomes the release-PR body.** Once a maintainer commits a changelog file for the resolved release version to `next`/`hotfixes`, that file's contents — not the auto-generated "What's Changed" summary — become the persistent release PR's body, and via the repo's `squash_merge_commit_message: PR_BODY` setting, the squash-merge commit message on the release branch. The contributor block is still appended either way, so contributors are never lost when the file omits them. The body is regenerated on every push to `next`/`hotfixes`, reading the file fresh, so editing the changelog and pushing updates the release PR (and thus the eventual squash message). Matching is by **exact** resolved version — a release only ever uses its own version's file; with no match, the auto-generated changelog is used, so a patch never falls back to a different version's notes. Feature/fix PRs merging into `next`/`hotfixes` are unaffected: their body is always the generated changelog, since the file lookup is a no-op without a resolved release version. (#231)
- **Both `docs/changelog` and `docs/changelogs` are searched by default.** When no changelog directory is configured, the lookup now covers both the singular and plural spellings, so either convention works out of the box; an explicit `changelog-dir` still searches only that directory. Lookup order per directory (first exact-version hit wins): `<dir>/v<major>/v<version>.md`, `<dir>/v<version>.md`, `<dir>/<version>.md`. (#236)

## Fixed

- **`publish-gh-pages` runs `git` without a shell.** The docs-site publisher built `git` invocations as shell strings interpolating inputs/env (`target_branch`, `commit_message`, the tokenized remote URL, bot identity) — a command-injection risk (CWE-78/88, CodeQL `js/indirect-command-line-injection`). It now runs `git` via `execFileSync` with an argv array, so every value is a literal argument and can never be interpreted as shell syntax, and it redacts the `x-access-token` from both the echoed command and any thrown error's message/streams so the token can't leak into Actions logs. (#235)
- **Coverage badge floors the percentage instead of rounding up.** A repo at 99.9% functions coverage could display `100.0%`, because the badge rendered the average with `.toFixed(1)`, which rounds up. It now floors to the displayed precision, so a value below 100% never shows as 100%. (#230)

## Infrastructure

- **Prettier + eslint tooling on this repo.** The CLDMV canonical prettier + eslint flat config (`.configs/`), a `.prettierignore`, the lint/format npm scripts, and the pre-commit hook installer are added and the tree formatted to match — bringing `@cldmv/.github` itself onto the same lint/format hygiene it ships to its consumers. (#232)
