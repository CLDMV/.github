# v4.14.0 — 2026-06-14

Minor release adding satellite-package publishing — publish additional packages alongside the core at the same version and commit — plus a round of security and publishing hardening, with four follow-on patches.

## Added

- **Publish satellite packages alongside the core (R1).** The publish flow can carve and publish additional packages (`extra_packages`) at the same version and commit as the core, each getting its own npm + GitHub Packages publish and a `@scope/name@version` tag + GitHub Release. See `docs/conventions/satellite-packages.md`. (feat: 7f3fa26)

## Fixed

- **Satellite publishing hardened** — lockstep enforced in verify, dry-run tag handling fixed, the satellite glob matcher escapes `?`, satellite tags URL-encoded in release lookups and deduped by name, and the release path hardened per re-review. (fix: 42224b4, 7fbcdc7, 9300350, d400cd8)
- **CodeQL alerts resolved** — injection, regex, and dead-code findings, plus dropping the shell from the dry-run tag check. (fix: 9e55a92, 840616e)
- **`tag-health` always emits its summary JSON** from `fix-orphaned-tags`. (fix: 17678a0)

## Patch releases

- **v4.14.1** — wire the satellite entry-point inputs (completes v4.14.0). (fix: 3c869cb)
- **v4.14.2** — retry satellite publishing after a partial failure; each satellite publish/release is idempotent, so a re-run republishes only the missing ones.
- **v4.14.3** — the flow label reflects the change type, not always `feature`.
- **v4.14.4** — ruleset merge-method handling with a direct-merge fallback.
