# v4.33.0 — 2026-10-12

Minor release that holds dev-dependency-only release PRs instead of offering them as releases, adds `@cldmv-bot` comment commands starting with `rebase`, and stops bot reviews from leaving held `Release Merge` runs.

## Added

- **Deps-only release PRs are held.** `check-release-commit` classifies the pending range as deps-only when every changed file is a lockfile, something under `.github/`, or the root `package.json` with only `devDependencies` and `version` differing. Any other field, any other file, a missing manifest or a git error makes it a normal release, and a range containing an explicit `release:` commit is never held. A deps-only release PR gets the `release: deps-only` label, `release-merge` skips a labeled PR and writes a summary line, and the label is removed on the next refresh once a real change joins the range. The verdict is also exposed as a `deps-only` output of `check-release-commit`, `create-release-pr` and `update-release-pr`. `workflow-release-merge.yml` takes a new `hold_label` input (default `release: deps-only`; empty disables the hold). Dev-dependency bumps keep landing on `next` and nothing is committed to `master`. See `docs/conventions/deps-only-releases.md`. ([#374](https://github.com/CLDMV/.github/pull/374))
- **`@cldmv-bot` comment commands.** A comment starting with `@cldmv-bot` on a PR runs the matching command through the new `workflow-bot-commands.yml` reusable and the `automation/bot-commands.yml` consumer template. The first command is `rebase`: it rebases the PR head onto the base tip with `git rebase --onto`, re-signs the commits with the bot key, pushes with `--force-with-lease`, and replies with the result. For a branch cut before a release, `@cldmv-bot rebase from=<old merge-base sha>` makes the already-released commits drop out. Only commenters with write access or higher can run it. Fork PRs, the integration and release branches, and release PRs are refused, a conflict pushes nothing and lists the conflicting files, and unknown commands get a help reply. The comment body is only matched against a fixed command table, never interpolated into a shell. Because `issue_comment` workflows run from the default branch, a consumer's caller takes effect once it is on `master`. See `docs/conventions/bot-commands.md`. ([#375](https://github.com/CLDMV/.github/pull/375))

## Fixed

- **A Copilot review no longer leaves a `Release Merge` run waiting for approval.** The `release-merge.yml` caller now skips `pull_request_review` events unless the review is a human approval. GitHub holds a run triggered by a bot actor until a maintainer approves it, and it is not yet confirmed that a job-level skip clears that hold, so watch a consumer repo after this ships. If runs are still held, the arming step moves to `workflow_run`. ([#373](https://github.com/CLDMV/.github/pull/373))
