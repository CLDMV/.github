# v4.40.1 — 2026-11-22

Patch release: release-merge stops waiting forever on a check run that has finished but still reports `in_progress`.

## Bug Fixes

- **Release PR stuck on a finished check.** GitHub can return a concluded check run with a stale status: `in_progress` alongside conclusion `success` and a `completed_at`. release-merge decided whether a check was done from `status` alone, so it logged `waiting on 1 unfinished check(s)` on every run and the release PR never merged, even after a manual rerun of release-merge. A check run now counts as finished when its status is `completed` or it has a conclusion or `completed_at`, and its conclusion decides pass or fail as before. The release-merge unit tests now run in `npm test`. Fixes [#514](https://github.com/CLDMV/.github/issues/514). ([#515](https://github.com/CLDMV/.github/pull/515))

## Upgrade notes

- No caller changes. A release PR that is stuck this way today merges on the next release-merge run after this ships; rerunning the CI run that owns the stale check also works.
