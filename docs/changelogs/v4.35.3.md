# v4.35.3 — 2026-11-06

Patch release with two CI fixes. Feature PRs now get a type check before they merge, and the issue-linking jobs recognize closing keywords written as markdown links, `owner/repo#N` or full issue URLs.

## Bug Fixes

- **Type check on feature pushes and PRs.** The type check only ran inside the coverage jobs, which run on pushes to `next` / `hotfixes` and on release PRs, so a `feat/*` or `fix/*` PR could pass every check and then fail on `next` with a type error. `workflow-ci.yml` now has a `🔎 Type Check` job that runs once (not per matrix leg) wherever the `ci` matrix runs. It builds first with `coverage_build_command`, because `test:types` often resolves against `dist/`, and it honours `skip_type_check`, `skip_build` and `type_check_command`. When the command names an npm script the repo doesn't define, the job skips with a notice instead of failing. `reusable-coverage-badge.yml` now defaults `type_check_command` to `npm run test:types`, matching `workflow-ci.yml`, `reusable-coverage-pr-comment.yml` and the `ci.yml` template. Fixes [#432](https://github.com/CLDMV/.github/issues/432). ([#433](https://github.com/CLDMV/.github/pull/433))
- **Closing keywords in more forms.** `close-resolved-issues` and `mark-implemented-issues` only matched a keyword followed directly by `#N`, so a reference written as a markdown link (`[#109](…)` after the keyword) was missed and `mark-implemented` found no candidates. The extractor now also accepts `[#N](url)`, `owner/repo#N`, `[owner/repo#N](url)` and `https://github.com/owner/repo/issues/N`. The forms that name a repo only count when it's the repo the job runs in, and a PR URL doesn't count. The `close-resolved-issues` unit tests weren't part of `npm test`; they are now. Fixes [#430](https://github.com/CLDMV/.github/issues/430). ([#431](https://github.com/CLDMV/.github/pull/431))

## Upgrade notes

- No caller changes needed; both fixes ride the `@v4` tag.
- A repo that defines a type-check script but currently fails it will now see that failure on its feature PRs instead of only after merging into `next`. Fix the types, or set `skip_type_check: true` if the repo shouldn't be type-checked.
