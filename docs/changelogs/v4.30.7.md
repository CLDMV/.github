# v4.30.7 — 2026-10-04

Patch release fixing two ways the release pipeline could lose work after a release: `next-reset` dropped PRs that merged into `next` between the release merge and the reset, and `tag-health` deleted and recreated release tags, which turned published releases back into drafts and could lose the tag outright. It also makes the committed changelog file the GitHub Release body and adds a manual `sync-release-notes` workflow for repairing existing releases.

## Fixed

- **`next-reset` carries late merges onto the release instead of dropping them.** After a `next → master` release squash-merged, `next` and `hotfixes` were force-reset to the release commit unconditionally, so a PR that merged in the gap (typically a bot or Dependabot auto-merge seconds after the release) vanished: not in the release, not on the branch, still shown as merged. A new `reset-branch-after-release` action replaces `force-reset-branch` for both branches. A branch that is exactly the release PR's head is reset as before; one that already contains the release is left alone, so re-runs are safe; one with commits merged after the release PR was cut has each late first-parent commit replayed onto the release commit and published through the Git Data API, so GitHub signs it for the bot App, with the carried commits listed in the run summary and a comment on each affected PR. A replay conflict leaves the branch untouched, fails the job, opens an issue and comments on every affected PR. The hotfix lane's merge of `master` into `next` is unchanged. ([#361](https://github.com/CLDMV/.github/pull/361), fixes [#360](https://github.com/CLDMV/.github/issues/360))
- **Branch updates after a release are lease-guarded.** Every ref update is a compare-and-swap against the tip the plan was built from, first GraphQL `updateRefs` with `beforeOid`, then `git push --force-with-lease`. If the branch moved in between, the plan is rebuilt from the new tip rather than overwritten. Only when both paths are refused with the branch unmoved does a guarded REST force update run, followed by an audit of PRs merged into the branch since the release. The App token now requests pull-requests and issues write for the comments and the failure issue. ([#361](https://github.com/CLDMV/.github/pull/361))
- **Consumer repos no longer wait up to two minutes before syncing their branches.** The wait-for-tags gate polled the repo's own major tag, which has nothing to do with the `v4` actions a consumer runs; repos without such a tag always waited the full two minutes, and that delay was the window in which the lost merges landed. The gate now runs only in `CLDMV/.github`, whose release rolls the tags its own jobs resolve, and `sync-branches` starts immediately everywhere else. ([#361](https://github.com/CLDMV/.github/pull/361))
- **`tag-health` no longer deletes and recreates tags.** Push-triggered publishes created the `vX.Y.Z` tag lightweight and unsigned, so the `tag-health` run on `release: published` replaced it by deleting the remote tag and pushing a signed one. Deleting the tag behind a published release turns the release back into a draft, and when the re-push was rejected the tag stayed gone while the step still reported success ([CLDMV/configs](https://github.com/CLDMV/configs) v1.2.0 and v1.2.2 were left that way). `fix-unsigned-tags`, `fix-non-bot-tags` and `fix-orphaned-tags` now re-sign or re-point a tag with an atomic force-update, so a rejected push leaves the original tag in place, and they run git without a shell, passing tag messages through a file. `fix-unsigned-tags` re-publishes any release the update turned into a draft and fails the job if a release is left a draft or a tag is missing. ([#363](https://github.com/CLDMV/.github/pull/363), fixes [#362](https://github.com/CLDMV/.github/issues/362))
- **Release tags are signed at creation.** `reusable-publishing.yml` signs release tags whenever the GPG key secret is mapped, not only when `use_gpg` is passed, so push-triggered releases no longer start with an unsigned tag for `tag-health` to repair. ([#363](https://github.com/CLDMV/.github/pull/363))
- **Publishing fails when the release does not end up published and tagged.** `create-release` ends with a gate that fails unless the release is published and its tag exists; before, a draft or tagless release still reported success. `fix-orphaned-releases` also pages through every release instead of the first 30. ([#363](https://github.com/CLDMV/.github/pull/363))

## Changed

- **The committed changelog file becomes the GitHub Release body.** When `docs/changelog[s]/v<major>/v<version>.md` (or the flat `v<version>.md` form) exists at the release commit, `create-release` uses it as the release body, keeping the coverage and Contributors blocks. Either way, the duplicated `release: vX.Y.Z - …` subject line and the squash trailers are dropped. ([#363](https://github.com/CLDMV/.github/pull/363))
- **Stray mentions are neutralized in release bodies.** Accidental `@word` and `@org/team` text outside code is wrapped in code spans, so a header tag or scoped package name no longer pings an account or adds it to the release's contributors, while the handles in the Contributors block stay live. This replaces the old list of JSDoc tags escaped with a zero-width space. ([#363](https://github.com/CLDMV/.github/pull/363))

## Added

- **Manual `sync-release-notes` workflow.** A new `workflow-sync-release-notes.yml` reusable, `sync-release-notes` action and `release-companions/sync-release-notes.yml` consumer template rewrite existing GitHub Release bodies from the committed changelog files, including ones backfilled after the release shipped. The run also reports draft releases, versions with no tag, tags with no release and duplicate releases. It is a dry run by default, and each repair is a separate opt-in: `publish_drafts`, `create_missing_tags` (signed, at the `release: vX.Y.Z` commit), `create_missing_releases` and `normalize_all`. This repository runs it as `local-sync-release-notes.yml`. ([#363](https://github.com/CLDMV/.github/pull/363))

## Security

- **Markdown table cells escape backslashes.** The run-summary and PR-comment tables in `reset-branch-after-release` and `sync-release-notes` escaped `|` but not `\`, so a backslash in a commit subject or error message could undo the escape and break the table. CodeQL flagged both while the PRs were open ([#111](https://github.com/CLDMV/.github/security/code-scanning/111), [#112](https://github.com/CLDMV/.github/security/code-scanning/112)); a shared helper now escapes backslashes first, then pipes, and flattens line breaks. Neither alert reached a release. ([#361](https://github.com/CLDMV/.github/pull/361), [#363](https://github.com/CLDMV/.github/pull/363))

## Upgrade notes

- No caller changes are required; the fixes ride in through the `v4` tag. The `next-reset.yml` template's header comment changed but its jobs did not.
- To give releases published before their changelog file existed their curated notes, copy `release-companions/sync-release-notes.yml` into the repo and dispatch it, first as a dry run and then for real. Add `publish_drafts` or `create_missing_tags` if the dry run reports drafts or missing tags.
