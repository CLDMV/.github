# v4.32.0 — 2026-10-12

Minor release that adds a required check to the persistent release PRs: a release can no longer merge until its per-version changelog exists on the source branch.

## Added

- **`📝 Release Changelog` check on `next → master` and `hotfixes → master` release PRs.** A new `check-release-changelog` action runs as a `changelog-check` job in the Next Release and Hotfixes Release workflows. It reads the version the release PR ships from the PR title, then looks for the changelog on the source branch with the same resolution order as the release-body generator: the explicit `changelog-file` input, then `v<major>/v<version>.md`, `v<version>.md` and `<version>.md` under `docs/changelog` and `docs/changelogs`. The check fails with the expected path and branch when the file is missing, and turns green on the next push to the source branch once the doc PR merges. A missing "What's New" mention of the version in the README is a warning, never a failure. ([#376](https://github.com/CLDMV/.github/pull/376))
- **`CLDMV_SKIP_CHANGELOG_CHECK` opt-out.** Setting the repository Actions variable to `1` or `true` keeps the check running but reports success with a notice when the file is missing, so the required check is satisfied rather than absent. The check is enforced when it is unset. It is documented with the other `CLDMV_SKIP_*` variables in `docs/conventions/release-flow-v4.md`. ([#376](https://github.com/CLDMV/.github/pull/376))

## Upgrade notes

- No caller changes are required; the check rides in through the `v4` tag. A release PR with no changelog file shows a red `📝 Release Changelog` check until one lands on the source branch. Repos that keep no per-version changelogs set `CLDMV_SKIP_CHANGELOG_CHECK=1`.
- Add `📝 Release Changelog` to the release branch's required checks in the org ruleset if it should block the merge by name.
- This release's own check could not resolve until `v4` rolled, so the release PR that shipped v4.32.0 did not run it.
