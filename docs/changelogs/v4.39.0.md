# v4.39.0 — 2026-11-18

Minor release. `v4-bootstrap` now records each repo's branch model in an org custom property and leaves repos marked `legacy` or `custom` alone unless forced. `sync-release-notes` also gets more tolerant of the commit-to-PR lookup.

## Features

- **Branch model as a custom property.** `v4-bootstrap` takes a `branch_model` input (`v4`, `dev-trunk`, `legacy`, `custom` or `none`; the workflow defaults to `v4`) and writes it to the repo's `branch-model` org custom property. A repo already marked `legacy` or `custom` is skipped unless `force` is set, so a fleet bootstrap run can't overwrite a hand-tuned repo. If the property isn't defined in the org, or the App lacks the "Custom properties" permission, bootstrap logs a warning and carries on. The model and its values are described in [docs/conventions/branch-model.md](../conventions/branch-model.md). ([#488](https://github.com/CLDMV/.github/pull/488), resolves [#472](https://github.com/CLDMV/.github/issues/472))

## Bug Fixes

- **sync-release-notes release PR lookup.** When the commit-to-PR listing comes back without `merged_at`, `base` or `merge_commit_sha`, each candidate is now confirmed by reading the full PR instead of being dropped. A miss logs what the listing returned for each candidate, which is what's needed to finish [#468](https://github.com/CLDMV/.github/issues/468). ([#487](https://github.com/CLDMV/.github/pull/487))

## Upgrade notes

- No caller changes needed. To set a repo's branch model, pass `branch_model` when dispatching `v4-bootstrap`, or refresh `v4-bootstrap.yml` from the `release-flow-v4` template to get the input in the dispatch form.
- The property has to exist in the org (single select, values `v4`, `dev-trunk`, `legacy`, `custom`, `none`) and the bot App needs organization "Custom properties" read and write. Without either, bootstrap only warns.
