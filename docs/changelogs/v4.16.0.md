# v4.16.0 — 2026-07-09

Minor release replacing PR-time closing-reference propagation with release-time issue closing, followed by a long run of release-flow, scorecard, and CI hardening patches.

## Added

- **Close resolved issues automatically when a release lands (`close-resolved-issues`).** In the v4 staging-branch flow, GitHub's native keyword auto-close never fires — contributor PRs merge into `next` / `hotfixes` (not the default branch), and the release PR squash-merges a changelog rather than per-issue keyword text — so linked issues would otherwise stay open forever. This action does the closing itself once the release reaches master: it resolves the release PR from the commit's trailing `(#N)`, walks the PR's `base..head` range (one merge-commit per bundled contributor PR), and for each source PR sweeps its description, comments, and constituent commits for both a `<!-- gh-broker:resolves:N,M -->` marker and `Fixes/Closes/Resolves #N` keywords, then closes those issues. Wired into `reusable-publishing.yml` as a best-effort, real-releases-only job. (#140)

## Removed

- **`sync-closing-issues`** (added in v4.11.0) is removed in favor of `close-resolved-issues`. The v4.11 approach propagated closing references onto the release PR at PR time; the release-time approach closes the issues directly when the release actually ships — the point at which they're genuinely resolved. (#140)
