# v4.26.0 — 2026-09-05

Minor release bringing pnpm to first-class parity with npm and yarn across the whole pipeline (with package-manager auto-detection and frozen-by-default installs), decoupling SLSA build provenance into its own release-triggered workflow, and scoping org-label sync — plus a batch of release-flow and hotfix-redirector correctness fixes.

## Added

- **First-class pnpm + auto-detected package manager (yarn parity).** The `package_manager` input previously accepted `npm`/`yarn` but silently degraded pnpm to `npm ci`, breaking every `@cldmv/*` pnpm-workspace repo at install. It now defaults to **`auto`**, detecting the manager from the `packageManager` field (corepack standard) then lockfile/workspace signals (`pnpm-lock.yaml`/`pnpm-workspace.yaml` → pnpm, `yarn.lock` → yarn, else npm); an explicit `npm`/`yarn`/`pnpm` is honored verbatim. pnpm is wired end to end — install, corepack provisioning, script/tool routing, and publish (so `workspace:*` deps are rewritten in the published tarball) — and yarn is brought to real parity, including Yarn-classic (v1) safety: `npx` is left unchanged for yarn (only pnpm rewrites to `pnpm dlx`) and satellite packing uses a flag-less `yarn pack`. npm-only repos are byte-for-byte unchanged. (#261 → #267)
- **Frozen/CI installs by default, with an explicit opt-out.** Every install path (CI, coverage, lint-format, release/publish) runs a reproducible frozen install (`npm ci` / `pnpm|yarn install --frozen-lockfile`); a missing lockfile fails loudly rather than silently mutating one. The only opt-out is the repo/org Actions variable `CLDMV_SKIP_FROZEN_LOCKFILE=1`. Documented in `docs/conventions/package-manager.md`. (#261 → #267)
- **SLSA build provenance (`.intoto.jsonl`) for releases — as its own workflow.** A genuine SLSA build-provenance file is attached to releases (the OpenSSF Scorecard provenance tier). Because the SLSA generator must run as a reusable-workflow call — a job type that can't carry `continue-on-error` — it lives in a decoupled `reusable-provenance.yml` triggered by `release: published`, so a provenance hiccup lands in its own run and never reddens the release. It re-packs the exact build artifact the publish run uploaded (matched to the release tag's commit) so the signed subjects are byte-identical to what shipped, and is fail-open. A consumer example caller is included. Requires the org's allowed-actions policy to permit `slsa-framework/*`. (#243 → #268)
- **Org-label sync can be scoped to a repo list, and PR-label apply seeds catalog labels.** `sync-org-labels` gains a `repos` input to sync just a named set instead of the whole org (empty keeps the full-org sweep). And `sync-pr-labels` now seeds/corrects the labels it is about to apply from `data/github-labels.json` first, so a freshly onboarded repo no longer gets GitHub's default flat-gray auto-created labels while waiting for the weekly org sweep. Non-destructive and best-effort. (#263 → #266)

## Fixed

- **Release-PR changelog no longer races the API-pushed version bump.** On a release-PR refresh that pushes a fresh `chore: bump version` commit via the API, `get-pr-commit-range` could compute a range whose head was never fetched into the job's local checkout, silently emptying the release-PR changelog or crashing the labels step. It now resolves the head from local `HEAD`, and the changelog generator + commit-type step fail loudly instead of silently rendering an empty changelog. (#262 → #265)
- **hotfix-redirector: the App-token cherry-pick push now triggers CI.** The redirect cherry-pick pushed via an App-token URL, but `checkout-code` persisted the default `GITHUB_TOKEN` as an `http.extraheader` that overrode it, so the push authenticated as `GITHUB_TOKEN` — which suppresses `on: push` — and the redirected security PR sat `blocked` with no required check. `checkout-code` gains a `persist-credentials` input (default `true`); the redirector checks out with `persist-credentials: false` so the App-token URL authenticates the push and re-triggers CI. (#269 → #270)
- **hotfix-redirector: the cherry-pick signature guard fails closed.** The pre-push guard threw only when `%G?` was exactly `N`, so an empty result from a failed probe (or any other value) let an unsigned commit reach the hotfix lane, blocked by required-signatures. It's inverted to fail closed — push only when `%G?` is a definitely-signed status (`G`/`U`/`E`). (#271 → #272)
- **Branch-naming ruleset allows `feature/*` creation.** The org ruleset permitted only `feat/*`, so `feature/*` — documented and auto-PR'd — was rejected at creation; it's added to the allowed patterns, and the deliberately-loose `release/*`/`hotfix/*` workflow arm is documented as the ruleset being the authoritative gate. (#258 → #264)

## Changed

- **`pmCommand` only rewrites npm script/tool subcommands.** Command routing now rewrites only `run`/`test`/`start`/`stop`/`restart`/`exec`, leaving install-style subcommands (`npm ci`/`npm install`) untouched, so a command passed through the router can never become an invalid `pnpm ci`/`yarn ci`. (#267)
