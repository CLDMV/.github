# v4.45.1 — 2026-11-25

Patch release: branch naming is enforced by a per-repo ruleset that onboarding keeps in sync, replacing an org-level ruleset that was never in effect.

## Bug Fixes

- **Branch naming as a per-repo ruleset.** The "CLDMV branch naming convention" org ruleset from `scripts/setup-org-rulesets.mjs` wasn't in effect on any repo, so any branch name could be pushed. The script also didn't match the rulesets API: the `creation` rule takes no list of names, and ruleset ref patterns are fnmatch, so its regex `release/[0-9]+\.[0-9]+\.[0-9]+` could never match. Branch naming is now a fourth per-repo ruleset, "Branch Naming", built by `buildBranchNaming()` in the ruleset-generator builders. It targets every branch, excludes `ALLOWED_BRANCH_PATTERNS` and blocks creating the rest; admins and the bot App bypass it, and existing branches aren't affected. `org-bootstrap-repo`'s `rulesets` step writes it with `Protect Master`, `Protect Next` and `Protect Hotfixes`, so `v4-bootstrap` and org onboarding apply it with the token they already use. `release/` and `hotfix/` names must start with a digit, and the other prefixes accept nested names. The setup script is removed, `docs/conventions/branch-naming.md` describes the ruleset and how forks are handled, the ruleset generator gets a `naming.json` download, and `data/rulesets/naming.json` is checked against the builder by a new test. Fixes [#553](https://github.com/CLDMV/.github/issues/553) ([#554](https://github.com/CLDMV/.github/pull/554))

## Upgrade notes

- No caller changes. Re-run org onboarding (or `v4-bootstrap` on a single repo) to install the "Branch Naming" ruleset.
- Delete the old "CLDMV branch naming convention" org ruleset if it exists; nothing maintains it any more.
