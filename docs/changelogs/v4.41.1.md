# v4.41.1 — 2026-11-23

Patch release: a release PR title set by hand now survives the refresh and reaches the release commit, and generated titles stop being cut short at 55 characters.

## Bug Fixes

- **Hand-edited release titles are kept, and the length cap applies to the whole title.** Every push to `next` refreshed the release PR and rewrote its title, so a title edited before approval was put back before the squash. The generated suffix was also cut at 55 characters before `release: vX.Y.Z - ` was added: github-platform v0.6.0 shipped as `release: v0.6.0 - --stall stops a run with no output, --hold keeps the…`. The release check now outputs `title-candidates`, the suffix every commit in the range could generate. A refresh regenerates the title only when its suffix matches one of them, in full or cut with "…". Otherwise the text was written by hand and is kept. Either way, the title starts with `release: v<current version>`: a stale version is replaced and a removed prefix is put back. The 72-character cap now applies to the finished title, cut at a word boundary with trailing spaces trimmed, then "…". Both the update path and the create path's update-existing branch apply this. release-merge reads the title and body again just before the squash, so a last-minute edit is what lands, and it keeps the version prefix. Fixes [#523](https://github.com/CLDMV/.github/issues/523) ([#524](https://github.com/CLDMV/.github/pull/524))

## Upgrade notes

- No caller changes. A release PR whose title is still the old 55-character cut is recognised as generated and gets the full title on its next refresh.
