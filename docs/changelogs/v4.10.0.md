# v4.10.0 — 2026-05-29

Minor release adding an optional pre-push container-image scan to the Docker publish flow. Single-feature cut.

## Added

- **Optional pre-push Trivy gate for container publishing (`enable_container_scan`).** When enabled, `workflow-docker-publish.yml` builds the image to an OCI tarball, runs Trivy against the tarball, and only pushes to the registry (via `crane`) if the scan passes — a true pre-push gate, so a vulnerable image never reaches the registry. Multi-platform builds are supported (the OCI tarball preserves the manifest list). Opt-in, to preserve backward compatibility. (#97)

Tunables (all only apply when the scan is on): `scan_severity` selects which severities block; `scan_fail_on_severity` toggles hard-fail vs report-only (report-only still scans and uploads SARIF but pushes regardless); `scan_ignore_unfixed` skips vulns with no upstream fix (on by default, so unfixable CVEs don't stall publishes indefinitely); and `scan_sarif_upload` / `scan_sarif_category` upload results to the GitHub Security tab under a named category. The scan runs via the SHA-pinned `aquasecurity/trivy-action`.
