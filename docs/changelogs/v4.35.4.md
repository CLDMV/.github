# v4.35.4 — 2026-11-06

Patch release with two CI fixes. pnpm and yarn repos work again on Node 26, and `types:check` is now the one type-check script name across the fleet.

## Bug Fixes

- **corepack on Node 25+.** Node stopped bundling corepack in 25, and `lts/*` now resolves to Node 26, so `corepack enable` failed and pnpm/yarn repos died with `pnpm: not found`. A shared `enableCorepack()` helper installs corepack from npm when the binary is missing, then enables it. If either step fails it logs a warning and carries on, in case pnpm/yarn is already on `PATH`. `build-project`, `run-tests`, `create-package`, `install-dependencies`, `update-package-version` and the `setup-node` composite all call it, and the separate "Enable corepack" steps in the coverage, lint-format and type-check jobs are gone. npm repos skip it. Fixes [#437](https://github.com/CLDMV/.github/issues/437). ([#438](https://github.com/CLDMV/.github/pull/438))
- **`types:check` is the type-check script.** The fleet used `typecheck`, `test:types` and `types:check` for the same job, and the reusables defaulted to `test:types`. `workflow-ci.yml`, `reusable-coverage-badge.yml` and `reusable-coverage-pr-comment.yml` now default `type_check_command` to `npm run types:check`, and the `ci.yml` template, the setup guide and the lint/format convention follow suit. The type-check step in both coverage reusables now skips with a notice when the named script doesn't exist, the same way the `🔎 Type Check` job already did; before, a missing script failed the coverage job on `next` and on the release PR. [package-layout.md](../conventions/package-layout.md) fixes three names: `types:check` runs `tsc --noEmit` on the source and is what CI runs, `types:build` emits declarations, and `test:types` is kept for consumer-side tests of the published types. ([#436](https://github.com/CLDMV/.github/pull/436), [#440](https://github.com/CLDMV/.github/pull/440))

## Upgrade notes

- No caller changes needed for the corepack fix; it rides the `@v4` tag.
- A repo that relied on the old `test:types` default and has no `types:check` script now skips the type check with a notice, on feature PRs and in the coverage jobs. Add a `types:check` script (or set `type_check_command` in `ci.yml`) to keep it running.
