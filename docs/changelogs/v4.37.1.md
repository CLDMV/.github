# v4.37.1 — 2026-11-14

Patch release that fixes the version bump for a repo's first release. When the default branch's `package.json` had no `version` field, the release flow bumped the version again on every push to `next`, so the version drifted ahead of the committed changelog and the release PR could never pick it up.

## Bug Fixes

- **First release no longer re-bumps on every push.** `find-divergence` now reads a default-branch `package.json` with no `version` field as base `0.0.0` instead of an unknown base. An unknown base skipped the already-bumped check, so each push to `next` added another `chore: bump version` commit (CLDMV/internal-github-tools went 0.0.1 → 0.0.2 when its changelog PR merged). ([#473](https://github.com/CLDMV/.github/pull/473))
- **A bump only counts as applied while `package.json` still has it.** `check-release-commit` used to treat a version as bumped whenever a `chore: bump version to X` commit was in the range, even after a later bump moved `package.json` past X. The release PR would then carry X in its title while `package.json` said something else. It now bumps back to X in that case. ([#473](https://github.com/CLDMV/.github/pull/473))

## Upgrade notes

- No caller changes needed. A repo stuck on a drifted first-release version corrects itself on the next release-PR refresh: re-run its Next Release workflow (or push to `next`).
