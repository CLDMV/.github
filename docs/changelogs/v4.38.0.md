# v4.38.0 — 2026-11-15

Minor release that lets a repo with no Node project turn off the Node chain. Config-only and infra repos (k3s manifests, shell scripts, org config) used to run setup-node, install, the test matrix, type check, coverage and lint/format on every push, or fake their way around it with `paths_ignore: "**"` and empty lint/format commands.

## Features

- **`node_project` input.** Set `node_project: false` on `workflow-ci.yml` and the test matrix, type check, lint/format, coverage and CI summary jobs don't run. The reusable exposes a `no_node` output, and the `ci.yml` template's `required-check` uses it to post a passing `✅ Required PR Check` with its own "No Node project" message, so the release PR still gets its required check. ([#478](https://github.com/CLDMV/.github/pull/478), fixes [#477](https://github.com/CLDMV/.github/issues/477))
- **The same switch on the other callers.** `reusable-bundle-size.yml` skips the head/base builds and the compare and passes with a one-line summary. `workflow-next-release.yml` and `workflow-hotfixes-release.yml` still open and refresh the release PR but skip its build step. `workflow-publish.yml` skips build-and-test and still creates the tag and the source-only GitHub Release. ([#478](https://github.com/CLDMV/.github/pull/478))
- **Empty `build-command` skips the release-PR build.** `create-release-pr` and `update-release-pr` used to fail on an empty build command; they now skip the build step. ([#478](https://github.com/CLDMV/.github/pull/478))

## Documentation

- The workflow setup guide has a new section, "Config-only and infra repos (no Node project)", covering `ci.yml`, `bundle-size.yml`, the release workflows and `publish.yml` (with `publish_to_npm: false` and `release_source_only: true`).

## Upgrade notes

- Every input defaults to `true`, so existing callers don't change.
- For a repo with no Node code, add `node_project: false` to `ci.yml`, `bundle-size.yml`, `next-release.yml`, `hotfixes-release.yml` and `publish.yml`, and drop any `paths_ignore: "**"` or empty lint/format commands used as a workaround. The repo still needs a metadata-only `package.json` with `name` and `version`, because the release flow bumps the version there.
