# v4.35.6 — 2026-11-08

Patch release that gets the GitHub Pages site building again. Every Pages build had failed since v4.35.0 because the README template docs quoted Liquid-style double-brace tokens. The template now uses single-brace tokens, and `docs/` builds with Jekyll 4 from a workflow in this repo, so pages that quote GitHub Actions expressions show them as written.

## Bug Fixes

- **Single-brace README template tokens.** [README.template.md](../../examples/readme/README.template.md) and [readme-format.md](../conventions/readme-format.md) wrote placeholders as double-brace tokens. That is Liquid syntax, and the classic Pages build ran every doc through Liquid, so the docs that quoted the tokens failed the build. All 115 tokens are now single-brace (`{repo}`, `{description}`, …), the docs show them as inline code, and the leftover-token check is `grep -nE '\{[a-z_0-9]+\}' README.md`. `.configs/.prettierrc` turns off embedded code formatting for `README.template.md` so Prettier leaves the tokens in its code samples alone. ([#451](https://github.com/CLDMV/.github/pull/451))
- **Pages builds with Jekyll 4.** The classic "deploy from a branch" build is pinned to Jekyll 3.10, which runs Liquid even inside code spans, so a doc quoting `${{ … }}` rendered it blank. The new `local-pages.yml` workflow builds `docs/` with Jekyll 4.4 in the official `ruby:4.0` container and deploys it with `actions/deploy-pages`. `docs/_config.yml` sets `render_with_liquid: false` for every page and keeps the classic build's theme, Markdown and plugin settings, and `docs/Gemfile` pins the plugins the classic build loaded implicitly. The built site has the same files as the classic build. ([#452](https://github.com/CLDMV/.github/pull/452))

## Upgrade notes

- No caller changes needed. Consumers that copied the README template should switch their placeholders to single braces the next time they regenerate a README.
- This repo's Pages source is now "GitHub Actions" (Settings → Pages), which `local-pages.yml` needs.
