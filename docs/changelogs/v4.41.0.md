# v4.41.0 — 2026-11-22

Minor release: the runner image ships `newuidmap`/`newgidmap` and a subordinate id range for the runner user, so a test can map more than one user into a user namespace it creates.

## Features

- **uidmap and a subordinate id range in the runner image.** `unshare -U --map-users=auto --map-groups=auto -r` needs `newuidmap`/`newgidmap` and a range in `/etc/subuid` and `/etc/subgid`. The image had neither tool, and the base image's runner range started at 231072, outside the 0–65535 ids a k3s-test `--userns` pod owns. The image now installs `uidmap` and sets `runner:10000:50000` in both files. The tools get file capabilities (`cap_setuid`/`cap_setgid`) instead of setuid, because a setuid-root `newuidmap` would need `CAP_DAC_OVERRIDE` to open the caller's `uid_map`. They only work where no_new_privs is off and the bounding set keeps SETUID/SETGID, which is k3s-test `--multi-user` (CLDMV/github-platform#49); in CI jobs and normal test pods they fail with EPERM. The build-time gate checks the capabilities and the range. ([#518](https://github.com/CLDMV/.github/pull/518))

## Upgrade notes

- No caller changes. The runner image rebuilds when this release reaches master. Tests that need several users run under k3s-test `--multi-user` and map from 10000–59999.
