# v4.30.3 — 2026-10-02

Patch release that stops an in-repo feature PR from becoming mergeable before its tests finish.

## Fixed

- **A skipped PR-run mirror no longer satisfies `✅ Required PR Check`.** On an in-repo feature PR the `pull_request` run skips the mirror job, because the push run owns the status. A skipped job still posts a check under its name, and GitHub treats a skipped required check as passing, so the ruleset (and auto-merge) went green while the push run was still testing; a PR could merge mid-test or over a red result ([CLDMV/slothlet#553](https://github.com/CLDMV/slothlet/issues/553)). The mirror job in the `ci.yml` template and in this repo's `local-ci.yml` now has an expression name that resolves to `✅ Required PR Check` only on the paths that own the status. ([#346](https://github.com/CLDMV/.github/pull/346))

## Upgrade notes

- The fix lives in the caller, not the reusable. Re-sync `ci.yml` from the `core-cicd` template. v4.30.4 refines the same job, so syncing to v4.30.4 or later covers both.
