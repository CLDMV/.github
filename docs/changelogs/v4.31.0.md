# v4.31.0 — 2026-10-05

Minor release that makes `sync-release-notes` part of the standard v4 workflow set and lets it create missing release tags itself. Tag pushes now use a scoped App token with no unsigned fallback, and tag messages keep their Markdown headings.

## Added

- **`sync-release-notes` runs automatically as part of the standard v4 set.** The consumer template now runs on `release: published` and on pushes to the default branch that touch `docs/changelog[s]/**`, so a release page that was drafted or published with the wrong notes is repaired without a manual dispatch. Only creating missing releases stays dispatch-only, because each new release fires `release: published`. ([#365](https://github.com/CLDMV/.github/pull/365))
- **Missing version tags are created automatically.** `tag-health` and `sync-release-notes` create a missing `vX.Y.Z` tag at its `release: vX.Y.Z` commit, bot-signed, with the changelog as the tag message and at most 20 per run. ([#369](https://github.com/CLDMV/.github/pull/369))

## Fixed

- **Tag pushes use a scoped App token and never fall back to an unsigned push.** Every tag-writing job pushes with the bot App token requesting `contents` and `workflows`, instead of the `GITHUB_TOKEN` that `actions/checkout` persists. That persisted token caused the `refusing to allow a GitHub App to create or update workflow … without workflows permission` errors for tags on older commits. A refused push now fails the job. ([#369](https://github.com/CLDMV/.github/pull/369))
- **Tag messages keep their Markdown headings.** Tags are created with `--cleanup=verbatim`, so `#` heading lines in a changelog are no longer stripped as comments. ([#365](https://github.com/CLDMV/.github/pull/365))

## Dependencies

- `brace-expansion` 5.0.9 → 5.0.12. ([#367](https://github.com/CLDMV/.github/pull/367))

## Documentation

- The v4.30.7 release notes, a README "What's New" block, and changelog files for every previously shipped v4 release. ([#366](https://github.com/CLDMV/.github/pull/366))

## Upgrade notes

- Copy `release-companions/sync-release-notes.yml` into each consumer repo (it is now part of the standard set, including on the `dev` branch and the single-commit `master` of dev-trunk repos). No other caller changes are required.
